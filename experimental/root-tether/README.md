# Experimental ROOT TUN hot refresh

Pinned sing-tun: bca4bf029237e444104626bb25f947dda90b06b5 (the version selected by the existing core).

This branch is intentionally **not** used by the standard core build or the app. The planner reuses sing-tun's actual route/rule generators, preserves the immutable effective route exclusions (including SRS), and rejects changes to anything other than exact downstream selectors and explicitly tracked local prefixes. The experimental Netlink transaction is now implemented, but no live lifecycle calls it. Run `bash experimental/root-tether/check.sh` on a Linux Go builder with GitHub access.

The transaction compares the entire dedicated route table and rule priority window, applies exact add/delete operations, journals confirmed mutations and checks rollback. An uncertain state is distinguished from a verified rollback. The mock-kernel tests inject failures before and after each operation, a failed rollback, duplicates and external changes. The pinned RuleList decoder omits some rule attributes; this is not proof of exclusive ownership under concurrent external writers. The multi-message transaction is not atomic. Before any runtime integration, add serialization with native TUN close and Android VPN callbacks, ifindex revalidation, downstream forwarding protection, and acknowledgement. Confirm kernel dump normalization on real Android devices. Do not use the existing UpdateRouteOptions as a substitute: it replaces routes but not interface policy rules. The current startup and restart fallback stay unchanged until device testing validates the new transaction.

### Native lifecycle experiment

The isolated native-tun-lifecycle.patch serializes Start, Close, UpdateRouteOptions, Android VPN callbacks and the private refresh entry point. It checks ifindices and Android VPN policy before kernel operations, publishes routing fields only after verification, and blocks additional updates after uncertain outcomes. The patch is applied only by check.sh; normal builds remain unchanged. This is not an active IPC integration. A supervisor forwarding guard, verified recovery after an uncertain outcome, and Android device validation are required before enabling it. A check cannot make concurrent external kernel writers atomic.
